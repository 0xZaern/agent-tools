# testgen

Hand an AI agent a ready-to-fill test skeleton instead of making it write test cases from scratch.

`testgen` reads a TypeScript or JavaScript source file, extracts exported function signatures via the TypeScript compiler API, and emits a structured edge-case test skeleton (happy path, null, undefined, empty, boundary, and type-mismatch cases) for vitest or jest — so an agent can fill in expected values rather than generate the entire test structure.

---

## Install

```sh
npx testgen
```

Or as a library:

```sh
npm install testgen
```

---

## CLI Usage

```
testgen <file> [options]

ARGUMENTS
  file    Path to a TypeScript or JavaScript source file

OPTIONS
  --json              Output as compact JSON (default, agent-friendly)
  --md                Output as human-readable Markdown
  --text              Output as a ready-to-paste test file
  --stats             Print only the token-savings summary line
  --framework vitest  Test framework to target (default: vitest)
  --framework jest    Generate jest-compatible test stubs
  --function name     Drill into a single function by name
  --max-tokens N      Trim the digest to approximately N tokens
  -h, --help          Show help
  --version           Show version
```

### Examples

```sh
# Generate test skeleton as JSON
testgen ./src/utils/validate.ts

# Output a ready-to-paste test file
testgen ./src/utils/validate.ts --text > validate.test.ts

# Drill into one function
testgen ./src/services/auth.ts --function verifyToken

# Jest instead of vitest
testgen ./src/lib/math.ts --framework jest --md

# Token budget
testgen ./src/api.ts --max-tokens 2000 --json | some-agent-cli
```

### Sample output (--stats)

```
testgen [vitest]: digest ~1,400 tokens | raw ~8,200 tokens | 83% smaller | 6 functions, 38 cases
```

### Sample output (--text, trimmed)

```ts
// generated by testgen — framework: vitest
// 6 function(s), 38 test case(s)

import { describe, it, expect } from 'vitest';

describe('validateEmail', () => {
  // signature: function validateEmail(email: string): boolean
  import { validateEmail } from './validate.js';

  it('validateEmail() returns a result for valid input', () => {
    const result = validateEmail("test");
    expect(result).toBeDefined();
  });

  it('validateEmail() handles null email', () => {
    // @ts-expect-error intentional null
    expect(() => validateEmail(null as never)).toThrow();
  });

  it('validateEmail() handles empty string for email', () => {
    const result = validateEmail("");
    expect(result).toBeDefined();
  });

  it('validateEmail() handles very long string for email', () => {
    const result = validateEmail("a".repeat(10000));
    expect(result).toBeDefined();
  });
});
```

## Library Usage

```ts
import { getTestGen } from 'testgen';

const digest = await getTestGen('./src/utils/validate.ts');

console.log(digest.stats);
// { tokenEstimate: 1400, rawEstimate: 8200, savedPercent: 83, totalFunctions: 6, totalCases: 38 }

console.log(digest.skeletons[0].cases);
// [{ description: '...', category: 'happy-path', body: '...' }, ...]
```

### With options

```ts
import { getTestGen, formatText } from 'testgen';

// Single function drill-down with jest
const digest = await getTestGen('./src/services/auth.ts', {
  framework: 'jest',
  functionName: 'verifyToken',
});

console.log(formatText(digest));
```

## Output schema

```ts
interface TestGenDigest {
  sourceFile: string;
  framework:  "vitest" | "jest";
  skeletons:  FunctionTestSkeleton[];
  stats:      TestGenStats;
  generatedAt: string;  // ISO 8601
}

interface FunctionTestSkeleton {
  functionName:    string;
  signature:       FunctionSignature;
  cases:           TestCase[];
  importStatement: string;
}

interface TestCase {
  description: string;
  category:    "null" | "undefined" | "empty" | "boundary" | "type-mismatch" | "happy-path" | "error";
  body:        string;  // complete it(...) { ... } block
}

interface FunctionSignature {
  name:       string;
  kind:       "function" | "arrow" | "method" | "async-function" | "async-arrow" | "async-method";
  params:     FunctionParam[];
  returnType: string;
  exported:   boolean;
  async:      boolean;
  jsdoc?:     string;
}
```

---

## Generated case categories

| Category | What it tests |
|----------|--------------|
| **happy-path** | Valid inputs — expects a defined result |
| **null** | Each required param passed as `null` — expects throw or graceful handling |
| **undefined** | All params passed as `undefined` — expects throw or graceful handling |
| **empty** | String params = `""`, array params = `[]` |
| **boundary** | Number params at `0`, `-1`, `Number.MAX_SAFE_INTEGER`; strings at 10,000 chars |
| **type-mismatch** | Each required param passed the wrong type (`@ts-expect-error` suppressed) |

## vitest vs jest output differences

The `--framework` flag controls two things:

1. **Import line** — vitest stubs import from `'vitest'`; jest stubs omit the import (jest globals are injected automatically by the test runner).
2. **Async assertions** — async functions get a `resolves.toBeDefined()` chain for vitest; jest output uses the same shape since jest 27+ also supports it.

| Feature | `--framework vitest` | `--framework jest` |
|---------|---------------------|--------------------|
| Import line | `import { describe, it, expect } from 'vitest'` | _(none — jest injects globals)_ |
| Async happy-path | `await expect(fn()).resolves.toBeDefined()` | `await expect(fn()).resolves.toBeDefined()` |
| Error stubs | `expect(() => fn(null)).toThrow()` | `expect(() => fn(null)).toThrow()` |

Both frameworks use the same assertion API for the generated cases, so switching between them requires only changing the import line in the output file.

## What gets included

- Exported named functions (`export function foo(...)`)
- Exported arrow functions (`export const foo = (...)`)
- Public class methods (non-private, non-protected)

Private methods, internal helpers, and non-exported symbols are excluded.

---

## Token savings

Reading and understanding a 500-line source file to write test cases: ≈ 5,000 tokens of context. A testgen skeleton for 8 exported functions: ≈ 1,200 tokens = **76% reduction**. The agent fills in expected values, not the entire structure.
